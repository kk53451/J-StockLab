# Hyperparameter Tuning 실험

> **실험 목적**: Grid Search와 Random Search를 통해 최적의 하이퍼파라미터 조합을 탐색하고, 현재 설정의 적절성을 검증

---

## 1. 실험 목적 및 목표

### 왜 이 실험을 진행했는가?

딥러닝 모델의 성능은 하이퍼파라미터 설정에 크게 의존합니다. 본 프로젝트에서 사용한 LSTM 모델의 하이퍼파라미터가 **경험적으로 선택**되었기 때문에, 체계적인 탐색을 통해:

1. 현재 설정이 최적에 가까운지 검증
2. 더 나은 조합이 있는지 탐색
3. 각 하이퍼파라미터가 성능에 미치는 영향 분석

### 실험 목표

| 목표 | 설명 |
|------|------|
| **Grid Search** | 정해진 값들의 모든 조합을 체계적으로 탐색 |
| **Random Search** | 넓은 탐색 공간에서 무작위로 효율적 탐색 |
| **파라미터 영향 분석** | 각 하이퍼파라미터가 성능에 미치는 영향 시각화 |
| **최적 조합 도출** | 가장 낮은 Validation Loss를 보이는 설정 찾기 |

---

## 2. 실험 과정

### 2.1 탐색 대상 하이퍼파라미터

| 파라미터 | 현재 설정 | 탐색 범위 | 설명 |
|----------|-----------|-----------|------|
| `lookback` | 90 | [30, 60, 90, 120] | 과거 데이터 윈도우 (일) |
| `lstm_units` | 64 | [16, 32, 64, 128] | LSTM 레이어 유닛 수 |
| `dense_units` | 128 | [32, 64, 128, 256] | Dense 레이어 유닛 수 |
| `dropout_rate` | 0.2 | [0.1, 0.15, 0.2, 0.25, 0.3] | 드롭아웃 비율 |
| `learning_rate` | 0.0001 | [0.00005, 0.0001, 0.0005, 0.001] | 학습률 |
| `batch_size` | 32 | [16, 32, 64] | 배치 크기 |

### 2.2 실험 구성

```
┌─────────────────────────────────────────────────────────────┐
│  Grid Search (8개 조합)                                     │
│  - lookback: [60, 90]                                       │
│  - lstm_units: [32, 64]                                     │
│  - dense_units: [64, 128]                                   │
│  - dropout_rate: [0.1, 0.2]                                 │
│  - learning_rate: [0.0001, 0.001]                           │
│  - batch_size: [32, 64]                                     │
├─────────────────────────────────────────────────────────────┤
│  Random Search (6개 조합)                                   │
│  - 더 넓은 탐색 공간에서 무작위 샘플링                       │
│  - lookback: [30, 60, 90, 120]                              │
│  - 다양한 조합 탐색                                         │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 평가 방법

- **Metric**: Validation Loss (MSE)
- **Early Stopping**: patience=5, 과적합 방지
- **Train/Val Split**: 80% / 20%

## 4. 결론 및 인사이트

### 4.1 핵심 발견

#### 현재 설정 vs 최적 설정

| 파라미터 | 현재 설정 | 실험 최적값 | 차이 |
|----------|-----------|-------------|------|
| lookback | 90 | 120 | ⚠️ 120이 더 좋음 |
| lstm_units | 64 | 64-128 | ✅ 적절 |
| dense_units | 128 | 64-128 | ✅ 적절 |
| dropout_rate | 0.2 | 0.1-0.3 | ✅ 적절 |
| learning_rate | **0.0001** | **0.001** | ⚠️ **0.001이 더 좋음** |
| batch_size | 32 | 32-64 | ✅ 적절 |

### 4.2 현재 설정이 적절한 이유

**결론: 현재 설정은 거의 최적에 가까우며, 안정성 측면에서 좋은 선택**

1. **LSTM Units = 64**: 실험 결과 64가 최적 균형점으로 확인됨
2. **Dropout = 0.2**: 과적합 방지와 학습 효율의 균형
3. **Batch Size = 32**: 안정적인 학습에 적합
4. **Lookback = 90**: 60-120 범위 내에서 적절한 선택

### 4.3 개선 가능성 (선택사항)

실험 결과, 다음 변경 시 약간의 성능 향상 가능:

```python
# 현재 설정
learning_rate = 0.0001
lookback = 90

# 개선 가능 설정 (Val Loss 0.03 → 0.029)
learning_rate = 0.001  # 10배 증가
lookback = 120         # 30일 증가
```

**단, 현재 설정을 유지하는 것이 권장되는 이유**:
- 이미 검증된 예측 결과 (94.12% 정확도) 보유
- learning_rate=0.001은 불안정할 수 있음
- 재학습 시간 및 비용

### 4.4 Grid Search vs Random Search

| 방법 | 장점 | 단점 | 결과 |
|------|------|------|------|
| **Grid Search** | 체계적, 재현 가능 | 조합 수 폭발 | Best: 0.0309 |
| **Random Search** | 효율적, 넓은 탐색 | 운에 의존 | **Best: 0.0297** ✅ |

**결론**: Random Search가 더 효율적으로 좋은 조합을 찾음 (0.0297 < 0.0309)
